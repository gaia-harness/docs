These skills create new files in the React app that follow your project's conventions. Describe what you want, and the skill asks for anything missing. Paths below are relative to `apps/web/`.

Files and folders under `app/components`, `app/pages`, and `app/hooks` are kebab-case (like `price-card`), and lint enforces it.

## New Component

It first checks whether [shadcn/ui](https://ui.shadcn.com/) already offers the component (a dialog, tabs, a popover). If it does, it adds it as `app/components/ui/<name>.tsx`, which GAIA never edits. Otherwise it creates `app/components/<name>/index.tsx` and `tests/index.stories.tsx`, with a starter test attached to a story.

**Confirms:** name (kebab-case or PascalCase; the folder uses the kebab-case form), parent folder (default `app/components/`), and props.

**Triggers** when you ask to create a component, scaffold a card, make a button, or add a new component.

**Example phrasing:** "create a price-card component", "scaffold a user-avatar with a name and url prop".

A component cannot be created inside `app/components/ui`, which holds only shadcn/ui files.

## New Hook

Creates a custom React hook, `app/hooks/use-<name>.ts` (named export `useName`), with a `vitest-browser-react` test at `app/hooks/tests/use-<name>.test.ts`.

**Confirms:** name (`use-kebab` or `useCamel`), parameters, and return type.

**Triggers** when you ask to create a hook, make a `useFoo` hook, or describe state or effect logic you want to reuse.

**Example phrasing:** "make a useCountdown hook", "extract this into a useFormSubmission hook".

## New Route

Creates a route file, `app/routes/<group>.<name>.tsx`, and its page, `app/pages/<name>/page.tsx`, with `tests/page.stories.tsx`. The story's starter test checks for one top-level heading and one main landmark, plus the loaded data for a connected route and the submitted data for a form. The route file stays small; the UI lives in the page.

When you connect it to a service, it writes everything from loading the data to showing it on the page. Ask for the data to load in one of three ways:

| Ask for the data to load | What it writes |
|---|---|
| on the server | a server `loader` the page reads with `useLoaderData` |
| in the browser | a `clientLoader` and a `HydrateFallback` |
| through TanStack Query | a `clientLoader` that loads the data into the [TanStack Query](https://tanstack.com/query/latest) cache, and a page that reads it with `useSuspenseQuery` (needs Query installed) |

Ask for a list page (`<group>.<name>.tsx`) or a detail page (`<group>.<name>_.$id.tsx`, which takes an id from the URL). The page story gets its data from [MSW](https://mswjs.io/) mocks. To preview the files without writing them, ask Claude to show them first.

**Confirms:** name (kebab-case), group (`_public` or `_session`), and the data, action, and i18n options.

**Triggers** when you ask to create a route, add a page, scaffold a path like `/dashboard`, or wire up a route under `_public` or `_session`.

**Example phrasing:** "add a /pricing page in _public", "scaffold a projects list page in _session backed by the projects service".

A route not connected to a service can still get a `loader` for the page title and meta tags, and an empty `action`. On a connected route, an action is a create for a list page or an update for a detail page, checked against the service's input schema.

## New Service

Creates an API service in your API's folder under `app/services/`, which [`/gaia-init`](/getting-started/gaia-init/) names after your project. It writes [Ky](https://github.com/sindresorhus/ky) request functions that check responses against [Zod](https://zod.dev/) schemas, plus the schemas, URL constants, and types, and optionally MSW mocks under `test/mocks/<name>/`. With TanStack Query installed and a `get` endpoint, it also writes `queries.ts` with query keys and `queryOptions`.

**Confirms:** name (kebab-case), endpoints (any of `get`, `post`, `put`, `delete`), the schema as `name:type` pairs, and whether to include mocks.

**Triggers** when you ask to add a service, create the API for a resource, or wire up CRUD (create, read, update, delete) for a resource.

**Example phrasing:** "add a projects service with get and post", "wire up CRUD for tasks with mocks".

Fields can be text, numbers, true/false, dates with times, or one of a fixed set of values, and any can be optional: "a tasks service with get and post, where a task has an id, a title, an optional due date, and a status of open or done". To add `queries.ts` to an existing service, ask for its Query options.

The skill does not connect the service to a page; [New Route](#new-route) does that for a route.
