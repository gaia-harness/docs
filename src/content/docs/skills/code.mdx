These skills shape how Claude writes and reviews code. Each loads on its own when the task matches its trigger ([how triggering works](/skills/#how-triggering-works)). You don't call them by name.

## TypeScript

Patterns and conventions for [TypeScript](https://www.typescriptlang.org/):

- `type` rather than `interface` ([why](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#differences-between-type-aliases-and-interfaces)).
- Explicit return types on exported functions ([why](https://typescript-eslint.io/rules/explicit-module-boundary-types/)).
- No enums: use `as const` objects with types derived from them ([why](https://www.typescriptlang.org/docs/handbook/enums.html#objects-vs-enums)).
- No `switch`: use an object map or `if`/`else`.
- At most three positional parameters, with an options object beyond that ([why](https://eslint.org/docs/latest/rules/max-params)).
- `undefined` rather than `null` for a missing value your own code sets.
- [Zod](https://zod.dev/) 4's [`z.literal([...])`](https://zod.dev/api#literals) rather than `z.enum()`, with values sorted alphabetically.

**One source of truth.** Before Claude defines a constant list, union type, schema, or lookup map, it searches for an existing one and imports it. Every other form of the same set (a type, a schema) is derived from that one source. A map keyed by a union uses `satisfies Record<Union, ...>`, so when you add a member to the union, TypeScript reports an error everywhere the new member is not handled yet ([why](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-9.html#the-satisfies-operator)).

**Triggers** when writing or reviewing TypeScript: typing exports, choosing between `type` and `interface`, defining Zod schemas, defining a shared constant list or union, structuring function parameters, or avoiding switch statements and enums.

**Example phrasing:** "type this Zod schema", "should this be a type or an interface", "add a status to this union".

## Naming Conventions

Descriptive names that explain themselves, in any language: TypeScript, bash, workflow YAML, Dockerfiles. It flags vague names, abbreviations, and names that just repeat the type. The always-loaded `no-abbreviations` rule holds everything Claude writes to the same standard.

**Triggers** when naming or renaming an identifier, variable, constant, function, parameter, environment variable, workflow job, or Dockerfile `ARG`/`ENV`, or reviewing names.

**Example phrasing:** "name this hook better", "is `cfg` a good name here", "rename these env vars".

## React Code

Conventions for React components, pages, routes, hooks, and forms. Claude runs four checks before writing code:

- **Hook check**: before a `useEffect`, decide whether it should be an Effect at all (an Effect is for syncing with something outside React, like a browser API or the network). No `useMemo`, `useCallback`, or `memo` (see below). For a `useState` with no initial value, use `undefined`, not `null`.
- **Form element check**: plain HTML form elements are replaced with the [shadcn/ui](https://ui.shadcn.com/) controls in `~/components/ui/` (`Input`, `NativeSelect`, `Textarea`, `Checkbox`, `RadioGroup`, `Button`), grouped in `Field` parts and connected to the form with [Conform](https://conform.guide/). `@conform-to/zod` is imported from its `/v4` subpath, which lint enforces.
- **Translation check**: every string the user sees comes from `t()`.
- **React 19 idiom check**: `ref` as an ordinary prop (no `forwardRef`), `use()` rather than `useContext`, `<Context>` rather than `<Context.Provider>`, guarding against `count && <X />` rendering a stray `0`, and [React Router](https://reactrouter.com/)'s form handling instead of `useActionState`, `useFormStatus`, or `useOptimistic`.

**Memoization is left to the compiler.** React Compiler is on by default and caches values and components for you, so plain code needs no `useMemo`, `useCallback`, or `memo`. A manual memo is allowed in two cases, each with a comment naming it: a value passed into code the compiler does not compile, or a component the compiler skips (a bailout) where measurement shows the memo matters.

**Data loading.** Data that belongs to the URL loads through the route's `loader` (or a `clientLoader`). Data that belongs to a component loads through [TanStack Query](https://tanstack.com/query/latest), when your project has it enabled.

**Reuse first.** Before adding a dependency or writing a helper, Claude follows the reuse order in the [`coding-guidelines`](/reference/rules/#always-loaded-root) rule: code already in the project, then built-in browser APIs and elements (`Intl`, `URL`, `structuredClone()`, `<dialog>`), then a dependency you already have, then a new one, and only then custom code. Files in `app/routes/` stay thin, and the UI lives in `app/pages/`.

**Triggers** when writing or reviewing React components, hooks, or event handlers, deciding whether to extract a component, deciding whether a manual memo or `"use no memo"` is justified, debugging stale closures or infinite re-renders, weighing a new dependency, or choosing a React 19 idiom.

**Example phrasing:** "this useEffect is firing twice", "extract this section into its own component", "wire up a Conform form for sign-up".

## Styling

### Tailwind

Every color uses a shadcn role token, a color named for its job rather than its hue (`bg-background`, `text-muted-foreground`, `bg-primary`, `text-destructive`). One token covers light and dark themes. Lint fails raw palette classes (like `bg-blue-500`), color literals, and arbitrary color classes.

`cn` is the only helper for combining classes. It resolves conflicts, so a caller's `className` comes last and overrides the default. Write a conditional class as `cond && 'class'`. Variants with several classes use `cva`. Custom sizes use `rem`, never `px`.

**Triggers** when writing [Tailwind](https://tailwindcss.com/) classes, combining classes with `cn`, writing conditional classes, building variants, defining `@theme` tokens, picking `rem` or `px`, or working with breakpoints.

**Example phrasing:** "this needs a hover variant", "name this color token", "let the caller override the padding".

### Skeleton Loaders

Loading placeholders (skeletons) that match the real content's layout: the same HTML elements and font classes, plus a shared `shimmer` class, with a 200ms delay so a fast load does not flash. Translated text uses the same `t()` call as the real component, so widths match. The skeleton is hidden from screen readers, and the region that receives the content is marked busy.

**Triggers** when adding loading states, building skeletons for async data, handling pending route transitions, or preventing layout shift.

## Test-driven development

`tdd` runs the red-green-refactor loop, an opt-in tool for logic where writing the test first helps. `tdd-react` holds the frontend testing reference: stories, hook tests, [MSW](https://mswjs.io/), route tests, and [Playwright](https://playwright.dev/). See [Test-driven development](/workflow/tdd/).

**Triggers** when building features or fixing bugs, mentioning "red-green-refactor", asking for integration tests, or asking for test-first development.

**Example phrasing:** "let's TDD this", "write a red test for the login flow".

## Playwright CLI

Microsoft's [Playwright CLI](https://github.com/microsoft/playwright-cli) skill for browser automation, unchanged: navigate, click, type, take screenshots, manage cookies and storage, and run several sessions in parallel. [`/setup-gaia`](/getting-started/setup-gaia/) installs the `playwright-cli` command once per machine, and `/update-deps` offers to upgrade it.

**Triggers** when navigating websites, filling forms, taking screenshots, testing web applications, or extracting information from pages. You can also say "use playwright for ...".

## ESLint Fixes

Claude usually handles [ESLint](https://eslint.org/) errors well. This skill covers specific errors where this project expects a particular fix, and autofix conflicts where one rule undoes another. If you see Claude fixing an error the wrong way (for example, turning the rule off instead of fixing the cause), ask it to improve the skill for that error:

```text
You fixed that lint error by turning the rule off. Update the eslint-fixes skill so it fixes <rule> properly next time.
```

Lint requires every `eslint-disable` comment to give a reason after `--` (`@eslint-community/eslint-comments/require-description`).

## Accessibility Fixes

Fixes specific accessibility errors reported by [axe-core](https://github.com/dequelabs/axe-core): `color-contrast`, `label`, `image-alt`, `button-name`, `link-name`, `region`, `heading-order`, the `aria-*` rules, `tabindex`, `duplicate-id`, and others. For an error not on its list, Claude fixes it and re-runs the check. Fixes use role tokens and the `ui` controls, so they work in both themes.

**Triggers** when an axe rule name (like `color-contrast`) appears in the output of a story test under [Vitest](https://vitest.dev/) (`addon-a11y`), the Playwright accessibility helper (`apps/web/.playwright/a11y.ts`), or `code-audit-frontend`'s accessibility findings.
