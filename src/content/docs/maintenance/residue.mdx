`/gaia-residue` goes through the trade-offs reviewers accepted instead of fixing when a pull request merged, and you decide what happens to each one. It never changes code.

It runs like every [maintenance command](/maintenance/#how-maintenance-commands-run): from the main checkout, on its own branch, ending in one pull request. Type it yourself; Claude never starts it.

Accepting a trade-off keeps a pull request moving, but one nobody looks at again is forgotten, and filing every one as an issue would bury the backlog. `/gaia-residue` sits between the two: you decide once, after 30 days, whether each still matters, and only those worth fixing become [tech debt](/workflow/tech-debt/).

## What a residual is

When the [Code Audit Team](/workflow/code-audit-team/) clears a pull request, some findings are not fixed: one accepted as a known trade-off, or one let pass because it is outside the change in a file the pull request touches. Each is written into the merged pull request's description, under `## Accepted residuals (recorded, not fixed)` or `## Out-of-scope machinery findings (recorded, not filed)` (see [What gets recorded instead of filed](/workflow/tech-debt/#what-gets-recorded-instead-of-filed)). Each entry is a **residual**.

For each one, you choose:

- **Dismiss** (the default): the trade-off stands.
- **Keep**: snooze it for 14 days.
- **Promote**: file it as a `tech-debt` issue for [`/gaia-debt`](/workflow/debt/) to fix. Promote only with a reason; promoting freely grows the backlog.

Dismissals and keeps are recorded in a committed file, `.gaia/audit-residual-dismissals.jsonl`, so your team shares them. GAIA only adds to it; don't edit it by hand. A promotion is recorded by the issue it files.

## The statusline nudge

A residual is **aged** once its pull request merged 30 or more days ago. The statusline shows <Nudge cmd="gaia-residue" text="🧹 /gaia-residue (N residuals)" /> once **5 or more** aged residuals are still open (not dismissed, kept, or promoted). N counts every open aged residual, not just one batch. The count refreshes every 6 hours, and right after a run.

## The flow

`/gaia-residue` takes no arguments.

1. It reads the residuals from your merged pull requests, oldest first, in batches of 25.
2. For each one it shows how the reviewer recorded it, what could go wrong, the file and line it points to, and what that line says now. When the line is gone, it suggests dismissing it as probably fixed.
3. You answer **Dismiss**, **Keep**, or **Promote**, with the answer the evidence supports marked as recommended. Dismissals can be confirmed for a whole batch at once. A promotion asks for a severity and whether the finding is security-sensitive.
4. It keeps going, batch after batch, until no aged residual is left. Stopping at 4 would bring the nudge back as soon as one more turned 30 days old.
5. Once nothing aged is left, it offers to sweep the newer ones a batch at a time, or stop. Stopping costs nothing: they come back once they age.
6. Everything lands as **one pull request**, `chore(residue): ...`, and the run asks whether to merge it or leave it open.

The run ends with a [cost line](/models-and-context/cost/). In a long run, when the context reaches the [red band](/models-and-context/token-efficiency/#context-bands), it offers to continue or to clear and resume. Every decision is saved as it is made.

It never edits a file a residual cites, never files an issue without your answer for that residual, and a keep always expires.

## When the nudge stays up after a run

A promotion that could not file an issue leaves its residual open. That happens when GitHub is unreachable, the filing fails, you promote from a branch that wrote the cited line (run it again from `main`), or the finding is security-sensitive: [security findings are never filed publicly](/workflow/tech-debt/#security-findings). The run says how many are stuck. Run `/gaia-residue` again once filing works. Deal with a security-sensitive one privately, then dismiss or keep it on a later run.

If GitHub cannot be read at the start, the run says "this is not an all-clear" instead of reporting nothing open.

## Settings

- `GAIA_RESIDUE_KEEP_DAYS` (default 14): how long a **Keep** lasts.
- `GAIA_RESIDUE_CAP` (default 25): how many residuals one batch holds.

Ask Claude to set one in the `env` block of `.claude/settings.local.json` (your machine only), then restart Claude Code:

```text
Set GAIA_RESIDUE_KEEP_DAYS to 30 in the env block of .claude/settings.local.json.
```
