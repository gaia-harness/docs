`/gaia-forensics` turns a problem with GAIA itself into a bug report with a fixed layout and secrets removed, so you can file it without scrubbing your logs by hand. It only reads: it never changes, installs, or fixes anything.

## When to use it

Run it when something GAIA-related goes wrong, such as:

- A GAIA command that stopped partway through, such as a stuck `/update-gaia`.
- A hook that blocked a commit or tool call you expected to pass.
- A wiki sync, scaffold, or Quality Gate failure.
- A dev server problem caused by GAIA's configuration.

<Aside type="caution" title="Not for your own code">
Forensics covers only GAIA's own commands, hooks, and configuration. It is the wrong tool for a failure in your application code.
</Aside>

## How to invoke

Type it yourself; Claude cannot start it:

```
/gaia-forensics [optional one-line description]
```

Without a description, it asks what you were doing, what you expected, and what happened.

## The flow

1. **Capture.** Records your GAIA, Node, [pnpm](https://pnpm.io/), and Claude Code versions, the branch, and whether there are uncommitted changes, plus the state files for the kind of failure. It never copies the contents of your app code, wiki pages, `.env*` files, or `node_modules/`.
2. **Classify.** Sorts the failure into one of eight kinds (`init`, `update`, `wiki-sync`, `quality-gate`, `hook`, `scaffold`, `dev-server`, `other`), quoting the phrase in your description it matched.
3. **Diagnose.** Decides whether the cause is your setup (a wrong Node version, a missing env var, uncommitted changes) or probably a bug. When the evidence points both ways, it picks your setup, the more likely cause.
4. **Redact.** Strips secrets, identity details, and machine paths, then checks the result. If anything that still looks like a credential gets through, it stops instead of writing the report.
5. **Save.** Writes the report to `.gaia/local/forensics/`.
6. **Act on the diagnosis.** For a setup problem, it prints the steps to fix it and stops. Ask Claude to carry them out. For a probable bug, it offers to file an issue.
7. **Offer to file.** If the [GitHub CLI](https://cli.github.com/) (`gh`) is installed, it asks once whether to file the report on `gaia-harness/gaia`. GitHub drops the `gaia-forensics` label for anyone without triage access to the GAIA repository; forensics still files the issue and tells you the label is missing.
8. **Confirm.** Prints the report path and, if filed, the issue URL.

## The report

The report always has the same sections in the same order, so filed reports are consistent:

```markdown
---
class: <init|update|wiki-sync|quality-gate|hook|scaffold|dev-server|other>
gaia_version: <semver>
created: <YYYY-MM-DD>
gh_issue_url?: <url>
---

## Symptom
<one-paragraph user description, redacted>

## Classification
class: <tag>
evidence: <verbatim user phrase> + <named state file>

## Capture
gaia_version: <semver>
node: <version>
pnpm: <version>
claude_code: <version>
branch: <name>
dirty: <true|false>
class_state_files:
  - <repo-relative path>: <one-line summary>

## Reproduction context
<plain prose: what you were doing, what you expected, what happened>
```

The GitHub issue gets the same report as the local file. After filing, the local file gains the issue URL.

## Example

```
> /gaia-forensics quality-gate refused to merge after I bumped a package
```

```
Report saved: .gaia/local/forensics/<tree>/20260509T143022Z-quality-gate.md

File a GitHub issue for this report?
```

If you say no, the report stays local. To file it later, ask Claude:

```text
File the forensics report at .gaia/local/forensics/<tree>/<report-file>.md on gaia-harness/gaia the way /gaia-forensics files one: title "forensics: <class>, <one-line description>", label gaia-forensics, the body taken from the saved file unchanged.
```

File it unchanged: it was already cleaned of secrets when it was saved.

## Storage

`.gaia/local/forensics/` is gitignored, so reports stay on your machine unless you file them. Reports written in a [worktree](/workflow/work-lifecycle/#3-isolate) are deleted after the worktree is removed. Reports from your main checkout stay until you remove them.
