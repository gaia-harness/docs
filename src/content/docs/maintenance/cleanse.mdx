`/gaia-cleanse` checks what Claude remembers and what it loads at every session start (machine-local memory, `CLAUDE.md` files, and rules) against the wiki, the project's source of truth. It finds entries that repeat the wiki, disagree with it, or point at things that no longer exist, and files that make the always-loaded context too large. Then it asks you one question before changing anything.

It runs like every [maintenance command](/maintenance/#how-maintenance-commands-run): from the main checkout, on a branch of its own (a worktree by default, per your team's isolation policy), ending in a pull request.

## Why it helps

Memory and `CLAUDE.md` files load into every session as instructions. A stale entry, or one that contradicts the wiki, steers Claude wrong on every task, and every extra line costs tokens in every session. Claude Code's [memory documentation](https://code.claude.com/docs/en/memory) notes that specific, concise instructions are followed more consistently.

## When to use it

Run it after a stretch of work, or when Claude's starting context (everything it loads before you type anything) feels heavy. The statusline nudges you with `🔎 /gaia-cleanse (<reason>)`, showing the highest-priority reason:

- `resume draft`: a report is waiting to be applied.
- `<N> new memories`: machine-local memory has grown by 10 or more entries since the last applied cleanse.
- `<N> days since review`: 30 or more days since the last applied cleanse.
- `over budget`: an auto-loaded file is larger than its size budget (an oversized `CLAUDE.md`, nested `CLAUDE.md`, or rule).

## How to invoke

```
/gaia-cleanse
```

Researches, shows you what it found, and applies the changes only if you approve.

```
/gaia-cleanse "memory only"
```

A hint in quotes narrows which memory stores or files the research looks at. It can only narrow the search, never change the report, its checks, or a specific edit.

```
/gaia-cleanse --apply
```

Applies the most recent report again, to finish an interrupted run or retry changes that were skipped.

## What it looks at

| Store | Path | Auto-loaded? |
| --- | --- | --- |
| Machine-local project memory | `~/.claude/projects/<project>/memory/` | `MEMORY.md` (first 200 lines); entries on demand |
| Machine-local agent memory | `~/.claude/agent-memory/` | Per agent, on demand. Reported, never edited: it is shared by every project on the machine. |
| Project agent memory | `.claude/agent-memory/` | Per agent, on demand |
| Root `CLAUDE.md` | `CLAUDE.md` | Every session |
| Nested `CLAUDE.md` files | `**/CLAUDE.md` (for example `apps/web/CLAUDE.md`) | When the working directory matches |
| Project rules | `.claude/rules/*.md` | At session start, or on a `paths:` match |
| Wiki | `wiki/` | On demand. The reference the others are checked against. |

Each entry is classified:

- **DUPLICATE**: the wiki already says it, so the local copy is removed.
- **PROMOTE**: lasting knowledge that exists only in memory moves to a named wiki page.
- **KEEP-LOCAL**: it really does belong to this machine only (a personal preference, a path on this machine), so it is left alone.
- **STALE**: it points at a file, branch, or feature that no longer exists.
- **CONFLICT**: a memory entry disagrees with the wiki, so it is changed to match the wiki.

### What it does not touch

- **Conflicts between instruction files.** When two `CLAUDE.md` files, rules, skills, commands, or agents disagree with each other, this command does not decide between them. Run `/doctor prompt-audit` for those. An instruction file that contradicts the wiki is reported and filed as a `tech-debt` issue, never edited.
- **Files you do not own.** It edits only your project's own files and memory, and asks you per file. A problem in a file GAIA ships is reported for [`/update-gaia`](/maintenance/update-gaia/), and one in a third-party file for its vendor. Agent memory shared across the machine is only reported; ask Claude if an entry there needs changing.
- **The wiki's own redundancy and broken links.** Those belong to [`/gaia-wiki`](/maintenance/wiki/).
- **Rules from [`/gaia-codify`](/maintenance/codify/) are never removed because their problem stopped showing up.** That means the rule is working.

## The flow

1. **Research.** A Sonnet sub-agent writes a report to `.gaia/local/cleanse/` (gitignored). Each proposed change names the path, the content it expects there, and what replaces it.
2. **Verification round** (recommended, optional). When the report proposes changes, three reviewers check each one against the memory files, the wiki, and the repository, and drop or fix any that are wrong. Memory lives outside git, so a wrong delete can't be undone; this round catches it before you approve.
3. **One question**, in your session:
   - **Apply**: asks which of your own files it may edit, then applies the report on its own branch, files any out-of-scope problem as a `tech-debt` issue, commits, opens a pull request, and merges it.
   - **Discuss / refine**: talk it through. Claude updates the report and asks again.
   - **Decline**: delete the report. Nothing is applied, filed, or published.

When the report proposes no changes, the run finishes on its own, once a check confirms the report covered every memory and rules file. If it did not, Claude says what was missed and asks the usual question.

<Aside type="tip" title="Safe by default">
Running `/gaia-cleanse` researches and reports. Nothing in memory, rules, or the wiki changes until you choose Apply.
</Aside>

## What Apply changes

Apply removes files or sections the wiki already covers, moves lasting knowledge from memory to a named wiki page, and replaces text in an auto-loaded file with a link to the wiki page that covers it.

If a file changed after the report was written, its change is skipped and noted, never forced. A file with uncommitted changes is skipped too.

## Reports and resume

A report that was only partly applied can be finished with `--apply`. A report older than 24 hours applies with a warning; one older than 72 hours needs a fresh run.

Memory lives under `~/.claude/`, outside the repository, so memory edits are never committed. A run that only changed memory opens no pull request.

The run ends with a [cost line](/models-and-context/cost/).
