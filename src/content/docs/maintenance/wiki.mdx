The wiki at `wiki/` is for Claude, not for reading. It records the important facts about your project once (services, hook contracts, past decisions), so Claude reads them instead of working them out from the source on every request, which saves tokens. It stays current as commits land.

## When to use it

Some work updates the wiki as it goes: a plan can add a summary of what shipped, and Claude may update a page when it learns something lasting. Nothing makes every change do so, so the wiki can fall behind. `/gaia-wiki` catches up whatever the rest of your work missed.

When the wiki is 20 or more relevant commits behind, the statusline shows:

<Nudge cmd="gaia-wiki" text="🧠 /gaia-wiki (N commits)" block />

Run `/gaia-wiki` then, or ask in plain language, such as "sync the wiki".

## How to invoke

```
/gaia-wiki
```

It takes no arguments. It runs like every [maintenance command](/maintenance/#how-maintenance-commands-run): from the main checkout, in its own worktree cut from `main`.

## The flow

1. **Sync** brings the wiki up to date with the commits since its last sync.
2. **Consolidate** finds redundant or contradicting pages and asks you about each one.
3. **Lint** checks the wiki's health and fixes what it finds.
4. **One commit** with all three stages' edits, titled `wiki: <date> <time> UTC`.
5. **One pull request** with that title, outside the [code audit's](/workflow/code-audit-team/) scope and set to merge automatically.
6. Claude **waits for the merge**, removes the worktree and branch, pulls `main`, and clears the nudge.

When sync stops partway (a first run, a rewritten history, an interruption), consolidate and lint are skipped, and what sync finished still lands. A cancelled run commits nothing.

The run ends with a [cost line](/models-and-context/cost/), including the wait for the merge.

## The three stages

### Sync

Sync goes through every commit since the wiki last checked, skips those that change nothing the wiki describes, and updates the affected pages. When the wiki is more than 30 commits behind, it asks first: you can sync only the most recent 20 and treat the rest as done.

Sync decides which commits matter by the files they change. By default your source code is each React app's source folder, `apps/web/app/` in a new project. If your code also lives elsewhere, such as a backend, ask Claude, naming every folder to keep, since your list replaces the default:

```text
Make /gaia-wiki treat changes under apps/api/src as source code too, keeping apps/web/app/.
```

Claude records this under `gaia.wikiClassify` in the root `package.json`, which `/update-gaia` leaves alone.

### Consolidate

Consolidate looks for, most important first:

- **Supersession**: two pages cover the same subject, and the newer should take in the older.
- **Reversed decisions**: a decision page that reverses an older one.
- **Near-duplicate page names**: names in the same area that differ by at most two characters.
- **Orphaned subjects**: pages nothing links to, matching no concept or module, unchanged for 90 days.

For each finding you choose **Apply** (recommended: merge or retire the page and rewrite its links), **Keep both** (it is not raised again), or **Skip** (it comes back next run).

### Lint

| Check | Finds |
|---|---|
| Wiki drift | How many commits the wiki trails `HEAD`. |
| Dead paths | Repository paths in wiki text that no longer exist. |
| Narrative ID drift | SPEC and UAT numbers in prose where they should not appear. |
| Orphan pages | Pages no other page links to. |
| Frontmatter gaps | Pages missing `type` or `status`. |
| Empty sections | Headings with no content. |
| Broken wikilinks | Wikilinks that resolve to no page. |

Simple fixes apply without asking. Fixes that need judgment ask you. Every finding is fixed, filed as a `tech-debt` issue, or left alone by your choice.

## Cleanup at session start

At every session start, a GAIA hook deletes local wiki branches whose work has merged. When it finds one, it fetches once, with a time limit, and fast-forwards `main` if it is checked out with no uncommitted changes, so a run that ended before its merge landed never leaves `main` behind.

Two environment variables tune that fetch:

- `GAIA_WIKI_FETCH_TIMEOUT_SECONDS` (default 5, from 1 to 30): its time limit. `0` turns off the fetch and the branch cleanup.
- `GAIA_WIKI_FETCH_MINIMUM_INTERVAL_MINUTES` (default 60, at least 5): the shortest gap between fetches. `0` removes the gap.

Ask Claude to set one in the `env` block of `.claude/settings.local.json` (your machine only), then restart Claude Code:

```text
Set GAIA_WIKI_FETCH_TIMEOUT_SECONDS to 15 in the env block of .claude/settings.local.json.
```

## What ships in the wiki

GAIA ships wiki pages describing what it installs, written as your project's own conventions. Ask Claude about any GAIA convention and it answers from them. Sections you add to a GAIA page are kept when [`/update-gaia`](/maintenance/update-gaia/) merges a new release.

[`/gaia-cleanse`](/maintenance/cleanse/) handles memory and auto-loaded files that duplicate or contradict the wiki.
