A GAIA project is a [pnpm](https://pnpm.io/) workspace, one repo holding several packages. The root holds the Claude setup and tooling shared by the whole repo. Apps live under `apps/`, and libraries shared between apps live under `packages/`. A new project has one app, the React app in `apps/web/`, with its own Claude setup.

## The root

| Path | What it holds |
|---|---|
| `CLAUDE.md` | Project instructions Claude reads at every session start |
| `.claude/` | Shared commands, skills, agents, hooks, rules, and settings |
| `.gaia/` | GAIA's CLI, scripts, and team settings, plus state kept only on your machine in `.gaia/local/` (gitignored). See [`.gaia`](/reference/gaia-folder/). |
| `.githooks/` | Git's own `pre-commit` and `commit-msg` hooks |
| `.github/` | The Tests, Chromatic, and PR Conventions workflows, and your `CODEOWNERS` |
| `wiki/` | The project wiki Claude maintains |
| `.notebook/` | The [Notebook](/workflow/notebook/) of specs, plans, and research (gitignored, in your main copy of the repo only) |
| `apps/`, `packages/` | Your workspace packages. A new project has `apps/web/` and an empty `packages/`. GAIA's checks cover every [package](/reference/gaia-folder/#packagesjson). |
| `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml` | The workspace, with one lockfile for the whole repo |

`pnpm typecheck`, `pnpm lint`, and `pnpm test:ci` run in every package that has a script of that name, and keep going after a package fails so you see every error in one run. `pnpm dev`, `pnpm test`, `pnpm pw`, `pnpm build`, and `pnpm storybook` run in the web app. `pnpm test:shell` runs the [bats](https://github.com/bats-core/bats-core) tests for your shell scripts in `tests/shell/` (see [Testing another stack](/workflow/testing/#testing-another-stack)).

### Pinned dependencies

Every dependency is pinned to an exact version, so every install gets the versions you tested ([why](https://docs.renovatebot.com/dependency-pinning/#why-pin-dependencies)). Versions change only through [`/update-deps`](/maintenance/update-deps/), which waits until a release is [three days old](/reference/gates/#release-age-window).

## apps/web/

| Path | What it holds |
|---|---|
| `apps/web/CLAUDE.md` | Instructions for sessions working on the app |
| `apps/web/.claude/` | The app's skills, rules, and Code Audit Team extensions. Its `settings.json` is generated, so ask Claude to change settings for the app and GAIA regenerates the file. |
| `apps/web/app/` | The [React Router](https://reactrouter.com/) app: `routes/`, `pages/`, `components/` (with [shadcn/ui](https://ui.shadcn.com/) in `components/ui/`), `hooks/`, `services/`, `state/`, `languages/`, `styles/` |
| `apps/web/test/` | Test setup, mocks, and utilities |
| `apps/web/.storybook/` | [Storybook](https://storybook.js.org/) config |
| `apps/web/.playwright/` | [Playwright](https://playwright.dev/) specs and helpers. `flows/` holds one test for each of a SPEC's [critical flows](/workflow/spec/#critical-flows), named after the flow |
| `apps/web/.env` | Your environment file (gitignored), copied from `apps/web/.env.example` |

File and folder names are kebab-case:

- **Components:** `apps/web/app/components/<name>/index.tsx`
- **Pages:** `apps/web/app/pages/<route path>/page.tsx`
- **Hooks:** `apps/web/app/hooks/use-<name>.ts`

Tests and stories are colocated in a `tests/` folder, so a refactor that moves a component's folder never leaves its tests behind, and the code folder stays tidy.

Your main copy of the repo and each worktree get their own dev, Storybook, and Playwright [ports](/workflow/work-lifecycle/#ports-per-worktree).
## The frontend stack

- **React and React Router**, with routes from file names (`@react-router/fs-routes`) in one flat folder.
- **React Compiler**, on by default everywhere.
- **shadcn/ui** on [Base UI](https://base-ui.com/), with [`lucide-react`](https://lucide.dev/) icons and [Conform](https://conform.guide/) for forms.
- **[Tailwind](https://tailwindcss.com/) v4 with role tokens.** Every color is a named role (primary, muted) defined once in `apps/web/app/styles/theme.css`.
- **Services** use [Ky](https://github.com/sindresorhus/ky) for requests and [Zod](https://zod.dev/) to check every response. A route loads data on the server, in the browser, or through [TanStack Query](https://tanstack.com/query/latest).
- **Testing built in** ([how it works](/workflow/testing/)). Each story is one visual state, with behavior tests attached, run in a real browser under [Vitest](https://vitest.dev/) and checked for accessibility. [MSW](https://mswjs.io/) mocks the API, so tests run without a backend. [Chromatic](https://www.chromatic.com/) screenshots each story in light and dark mode.
- **Translations (i18n)** with react-i18next (unless you removed them during `/gaia-init`).
- **`@gaia-harness/lint`** for [ESLint](https://eslint.org/), [Stylelint](https://stylelint.io/), and [commitlint](https://commitlint.js.org/), with [Prettier](https://prettier.io/) and [Knip](https://knip.dev/).

A new project starts unbranded, with gray-scale colors and system fonts, until you settle on your own design.

## Why no backend?

GAIA ships one frontend framework and no backend, on purpose.

### The frontend is chosen for you

You can build nearly any web app with React Router. It is widely used and well established, it renders on the server or runs entirely in the browser as a single-page app, and it deploys almost anywhere (see [Deployment](/getting-started/deployment/)). Other frameworks rarely decide whether you *can* build your app, so GAIA settles the choice for you. If React Router truly cannot do what you need, Claude can replace it, but GAIA's frontend rules, skills, and Code Audit Team extensions would have to change with it.

### The backend is left to you

Backends depend on your language, hosting, database, and what your company already runs. GAIA works with any of them, from a hosted service such as Supabase to an existing company API.

A backend you add becomes another app, such as `apps/api/`, with its own `CLAUDE.md`, rules, and skills. To add one, ask Claude, and GAIA registers it so its checks know where its source and tests are. Then:

- **Quality Gate.** The gate runs each package's own `typecheck`, `lint`, and `test:ci` scripts, so give the backend those scripts. GAIA warns about a package with tests but no `test:ci`, or TypeScript but no `typecheck`.
- **Code Audit Team.** `code-audit-frontend` already reviews everything under `apps/` and `packages/`, skipping its React app checks on other packages. For a review written for your backend's stack, ask Claude to add a member. See [Covering new code](/workflow/code-audit-team/#covering-new-code).
- **CI.** `tests.yml` typechecks and tests every package but lints only the web app. For backend lint or other checks in CI, ask Claude to add a workflow.

<Aside type="note">
Worktree ports cover the web app only. Before running backend work in a worktree, GAIA asks whether worktrees should share one backend or each run their own.
</Aside>
