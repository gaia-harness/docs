`/setup-gaia` sets up a GAIA project on your machine and connects it to GitHub. On a new project, `/gaia-init` runs it for you. You can run it again any time. It checks what is still needed and runs only those steps.

It covers three things:

- **This machine**: tools, a plugin, and whether to use Claude Code's sandbox.
- **The GitHub repository**: creating or connecting it, and, if you are a repo admin, applying GAIA's recommended repo settings.
- **Team settings**: shared defaults your whole team uses.

Type `/setup-gaia` yourself; Claude does not start it when you ask in plain language. Run it from your main checkout, not a worktree.

## When to use this

- After cloning an existing GAIA project, once per machine.
- When the statusline shows `⚙️ /setup-gaia`.
- To connect GitHub to a project that skipped it.
- On a new project, only if `/gaia-init` stopped before setup finished.

On a project that is fully set up, it changes nothing.

## The flow

### 1. Prerequisites

Setup checks these every time:

- **Tool versions.** [git](https://git-scm.com/), [jq](https://jqlang.org/), and `lsof` on macOS or `ss` on Linux. If one is missing or too old, GAIA walks you through the update before setup goes on. A step that needs your password comes to you as `! <command>` to type in the prompt. See [Tools](/reference/tools/#checked-on-every-setup-and-update).
- **pnpm and Chromium.** Setup installs [pnpm](https://pnpm.io/) and [Chromium](https://www.chromium.org/), the browser GAIA's tests run in, if they are missing. It asks before updating an older pnpm. See [pnpm](/reference/tools/#pnpm) and [Chromium](/reference/tools/#chromium).
- **Worktree links.** Checks that this checkout can share GAIA's local state with [worktrees](/workflow/work-lifecycle/). On Windows this can need Developer Mode turned on.
- **Git hooks.** If GAIA's [git hooks](/workflow/git-conventions/#native-git-hooks) are off, setup asks to turn them on.
- **GitHub CLI.** If `gh` is missing or not logged in, setup warns and carries on. GAIA's pull request workflow needs it, so install it from [cli.github.com](https://cli.github.com/) and run `gh auth login`.

### 2. Per-machine setup

Runs once per clone:

- Installs the [React Doctor](https://github.com/millionco/react-doctor) skill and the [Playwright CLI](https://github.com/microsoft/playwright-cli).
- Installs the TypeScript language server plugin, so Claude can jump to definitions and see type errors.
- Creates `apps/web/.env` from `apps/web/.env.example`.
- Asks about the sandbox, if your team recommends it.

#### Sandbox decision

Claude Code's [sandbox](https://code.claude.com/docs/en/sandboxing) limits what shell commands can reach. GAIA works inside it, but it blocks `gh`, git over HTTPS, and `docker` until you allow each one, so it is opt-in.

Setup asks about it only when your team recommends it. If your machine can't run the sandbox, setup tells you what it needs: WSL2 on Windows, or bubblewrap and socat on Linux. Your answer applies to this machine only and takes effect in your next Claude Code session.

### 3. GitHub repository

On a new project, this is the first question:

- **Create the repo on GitHub** (recommended). You choose your personal account or one of your organizations. The repo is private unless you confirm otherwise. Setup pushes your default branch and turns on GitHub's secret-scanning push protection where GitHub offers it.
- **Use an existing repo.** Nothing is created.
- **Set one up manually.** Setup prints the commands. Run `/setup-gaia` again once you have pushed.

If `.github/CODEOWNERS` still has the placeholder owner from `/gaia-init`, setup offers to fill in your GitHub handle.

#### Recommended defaults (admin only)

If you are a repo admin, setup applies GAIA's recommended repo settings:

- **Branch protection** on the default branch, if it has none. Approvals are not required, so you can merge your own pull requests.
- **Required checks.** A pull request can merge only after it passes GAIA's [code review](/workflow/code-audit-team/) and its tests, even when someone merges it on github.com.
- **Delete branches on merge.**
- **Auto-merge**, so GitHub merges a pull request once its checks pass.
- **Security fixes.** GAIA's [`/update-deps`](/maintenance/update-deps/#why-not-dependabot-pull-requests) fixes vulnerable packages and tests every fix before it merges. [Dependabot](https://docs.github.com/en/code-security/dependabot) alerts stay on, but Dependabot's fix pull requests are turned off to let GAIA handle them.

On a repo setup just created, it applies them all without asking. On an existing repo, it asks before turning on branch deletion and auto-merge.

If you are not an admin, setup skips these and tells you what an admin needs to do. The rest of setup still finishes.

### 4. Team settings

Two settings are shared with your team through `.gaia/project.json`:

- **Isolation policy.** Whether each task runs in its own [worktree](/workflow/work-lifecycle/#isolation-policy). Default: always.
- **Sandbox recommendation.** Whether setup suggests the [sandbox](#sandbox-decision) to each teammate. Default: no.

`/gaia-init` sets the defaults, so a plain run asks nothing. A repo admin changes them with [`--reconfigure`](#reconfiguring).

### 5. Squash-only merges

Claude always squash-merges, so each pull request lands as one commit titled with the pull request's title. GAIA makes merges on github.com work the same way. If you are a repo admin, setup turns on squash-only merges. On a repo it just created, it does so without asking. On an existing repo, it asks, and you can keep your current merge settings.

### 6. Labels

Setup adds GAIA's [labels](/reference/labels/) to your GitHub repo, leaving your label colors alone. If you can't edit labels, it prints the commands for someone who can, and carries on.

### 7. Statusline

If you already use your own Claude Code statusline, setup asks how to combine it with GAIA's. See [Using your own statusline](/workflow/statusline/#using-your-own-statusline).

### 8. New setup steps from later releases

A GAIA release can add a setup step. `/setup-gaia` runs any new step you haven't done yet, so you never set up again from scratch. Some steps need a repo admin. If you are not one, setup says the step is waiting for an admin.

### 9. Finish

Setup ends by telling you whether anything is left, such as a setting that needs a repo admin. When a repo admin runs it on the default branch, the team's answers are committed and pushed so the whole team gets them.

Type `/clear` to start your first feature with a fresh context. See [Onboarding, as you build](/getting-started/onboarding/) for what happens next.

## Reconfiguring

`/setup-gaia --reconfigure` asks these questions again, and nothing else:

- The sandbox decision on this machine
- The team isolation policy (repo admins only)
- Squash-only merges (repo admins only)
- How your own statusline combines with GAIA's

## On failure: re-run

Fix the cause and run `/setup-gaia` again. It picks up at the first unfinished step. If Claude Code's auto mode blocks a step, type `/setup-gaia` again and approve the action when Claude Code asks.
