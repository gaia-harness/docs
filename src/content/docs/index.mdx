One command creates a new GAIA project, then launches Claude Code to finish setup.

<Aside type="caution" title="Run GAIA in a terminal">
Open a terminal to run `npx create-gaia` and `claude`. Many of the Claude Code features GAIA uses aren't in the Claude Desktop app yet.
</Aside>

## Prerequisites

- Node 22.22.0 or later. Check with `node --version`.
- Claude Code 2.1.287 or later, reachable as `claude`. Run `claude update` if you are on an older version.
- The [GitHub CLI](https://cli.github.com/), `gh`, authenticated with `gh auth login`. GAIA's pull request and merge workflow runs on it.

`pnpm` is not required up front. If `pnpm install` runs (the default) and [pnpm](https://pnpm.io/) is missing, `create-gaia` installs it for you. With `--no-install`, it installs nothing. GAIA uses pnpm 12, pinned in `package.json`.

## New GAIA project

To start a new project, run this in the terminal:

```bash
npx create-gaia@latest my-app
```

`my-app` becomes the project directory. It must be empty or not exist yet. `create-gaia` won't write into a folder that already has files in it.

1. Downloads the latest GAIA release bundle and extracts it
2. Runs `git init` and creates a single `chore: scaffold from GAIA <version>` commit
3. Installs the packages
4. Launches Claude Code in the project directory and runs `/gaia-init` automatically

Follow along with the `/gaia-init` [walkthrough](/getting-started/gaia-init/). Once setup is done, the [Workflow overview](/workflow/) shows how a normal session works, and [Onboarding, as you build](/getting-started/onboarding/) shows what GAIA does as your first commits and pull requests land.

The project is a pnpm workspace: the shared Claude setup at the root, and the React app in `apps/web/`. See [Project layout](/getting-started/project-layout/).

### Permissions on the first run

`npx create-gaia` starts Claude Code in [auto mode](https://code.claude.com/docs/en/permission-modes), which skips routine permission prompts. Setup rewrites files, installs tools, and connects GitHub, so in the default mode it would stop to ask your permission many times. If auto mode is not available to you, setup still runs and asks more often.

The session stays in auto mode after setup ends. Press Shift+Tab to leave it. A new session starts in your usual mode.

### Guardrails

Every GAIA project comes with hooks that stop Claude from the risky actions an agent should never take, such as:

- Committing or pushing directly to `main`, or force-pushing it
- `rm -rf` on dangerous targets (`/`, `~`, `.git`, `.claude`, `node_modules`, the repo root)
- Reading `.env` files, keys, and credentials, or writing secrets into the repo
- Committing with `--no-verify`, which would skip the typecheck, lint, and tests the pre-commit hook runs
- Opening a pull request that is not a draft, or whose title is not a Conventional Commit
- Merging a pull request the [Code Audit Team](/workflow/code-audit-team/) has not cleared

When a GAIA hook blocks an unsafe action, Claude takes the safe route. See the [hooks reference](/reference/hooks/) for the full set.

## Cloning an existing GAIA project

For a project that already exists (for example, one a teammate created), clone the repo, then:

1. Run `claude --permission-mode auto`
2. Run `/setup-gaia` in Claude Code

Follow along with the `/setup-gaia` [walkthrough](/getting-started/setup-gaia/).

<Aside type="note">
You can leave out `--permission-mode auto`. Setup then stops to ask your permission more often.
</Aside>

## Pinning to a specific version

To install a specific version of GAIA instead of the latest:

```bash
npx create-gaia@latest my-app --version v2.0.0
```

Other flags: `--no-install` skips the dependency install, `--no-git` skips `git init` and the first commit, and `--no-claude` skips launching Claude Code. It prints the next steps instead: `cd` into the project, run `claude --permission-mode auto`, then run `/gaia-init` in Claude Code. You get the same steps when the `claude` command is not installed.
