GAIA adds a [statusline](https://code.claude.com/docs/en/statusline) to Claude Code: the row under the prompt. It has two sides, and each answers a different question:

- **The left side** is about the session you are in: which project and branch, which model, how full Claude's context is, and how much of your usage limits you have used.
- **The right side** is about the project: which GAIA commands are due, and why.

Both sides share one row. They are shown separately below.

## The left side

<Row><S c="#60a5fa">my-app</S> │ <S c="#4ade80">🌳 feat/login</S> │ <S c="#22d3ee">Opus 5.5 (High)</S> │ <S c="#4ade80">▓▓░░░░░░░░</S> 18% │ 🕔 <S c="#4ade80">23%</S> │ 📅 <S c="#4ade80">41%</S></Row>

| Segment | What it shows |
| --- | --- |
| Project | The main checkout's folder name. A [linked worktree](/workflow/work-lifecycle/#why-gaia-works-in-worktrees) shows the same name, so you always see which project you are in. |
| Branch | The branch the session is on. A `🌳` in front means the session is in a linked worktree, a separate copy of the repo on its own branch. |
| Model and effort | The model, with its effort level in parentheses when one is set: `Low`, `Medium`, `High`, `XHigh`, or `Max`. |
| Context bar | How full the context window is: ten cells, then the percentage of the window used. |
| Usage limits | How much of your 5-hour (`🕔`) and 7-day (`📅`) limits you have used. See [Usage limits](#usage-limits). |

### The context bar

A model's answers get worse as its context fills, and Claude cannot see how full its own context is. The bar shows you, so you know when to [clear and resume](/models-and-context/token-efficiency/#why-so-early). Its color follows the bands GAIA uses to decide when to ask you to clear:

| Band | Bar |
| --- | --- |
| Green | <code style={{ background: '#1a1b26' }}><S c="#4ade80">▓░░░░░░░░░</S> 9%</code> |
| Yellow | <code style={{ background: '#1a1b26' }}><S c="#facc15">▓▓▓░░░░░░░</S> 26%</code> |
| Red | <code style={{ background: '#1a1b26' }}><S c="#f87171">▓▓▓░░░░░░░</S> 31%</code> |
| 🔥 | <code style={{ background: '#1a1b26' }}><S c="#f87171">▓▓▓▓░░░░░░</S> 38% 🔥</code> |
| 💀 | <code style={{ background: '#1a1b26' }}><S c="#f87171">▓▓▓▓▓░░░░░</S> 46% 💀</code> |

The examples use a 1M-token window. Where each band starts is on [Token efficiency](/models-and-context/token-efficiency/#context-bands); what happens at each is on [Work lifecycle](/workflow/work-lifecycle/#resuming-long-work).

A yellow `⚠ override` after the percentage means your [checkpoint override](/models-and-context/token-efficiency/#context-bands) is out of range or unusable. With the checkpoint turned off, the bar stays green.

The statusline also saves each reading, which is how GAIA [tells Claude](/models-and-context/token-efficiency/#context-bands) when the context reaches a band. Without GAIA's statusline, Claude gets no band warnings, and the [audit checkpoint](/reference/gates/#audit-checkpoint) counts rounds instead.

### Usage limits

`🕔` and `📅` each appear once Claude Code has reported that limit to any session of the project. A limit it has never reported shows nothing, not 0%. The color shows how close you are, and the time in brackets is how long until the limit resets. The 5-hour limit shows that time from 75%, since its reset is near enough to plan around. The 7-day limit shows it from 90%, since at 75% its reset can still be days away.

| Used | 5-hour | 7-day |
| --- | --- | --- |
| Below 75% | <code style={{ background: '#1a1b26' }}>🕔 <S c="#4ade80">23%</S></code> | <code style={{ background: '#1a1b26' }}>📅 <S c="#4ade80">41%</S></code> |
| 75% or more | <code style={{ background: '#1a1b26' }}>🕔 <S c="#facc15">78%</S> (1h40m)</code> | <code style={{ background: '#1a1b26' }}>📅 <S c="#facc15">80%</S></code> |
| 90% or more | <code style={{ background: '#1a1b26' }}>🕔 <S c="#f87171">92%</S> (1h2m)</code> | <code style={{ background: '#1a1b26' }}>📅 <S c="#f87171">93%</S> (1d6h)</code> |

Every session of the project shows the same figures, including sessions in linked worktrees. Each session saves its own reading, and each limit shows whichever session's figure changed most recently. A limit that falls, because it reset or you switched accounts, shows at once. Once a window has passed, its limit shows `reset`.

To see each limit with its reset time and how fast it is climbing, ask Claude:

```text
Show me the current usage limit reading.
```

GAIA stops Claude from changing or deleting the saved figures. If one is ever wrong, delete the files in `.gaia/local/cache/shared/rate-limits/` in the main checkout from your own terminal outside Claude Code. Each session's statusline writes fresh figures on its next refresh.

### When a limit runs high

Before the main session hands work to agents, GAIA checks that session's own reading of each limit. The first time a limit reaches its warning level in a session, and again at its critical level, GAIA tells Claude the figures and when they reset. If a figure falls and later climbs back, GAIA tells Claude again. The 5-hour limit warns at 75% and turns critical at 90%. The 7-day limit follows your plan: 75% and 90% on most plans, 80% and 92% on Max 5x, and 85% and 95% on Max 20x. If GAIA cannot read your plan, it uses 75% and 90%. The agents Claude was about to start still start. The figures shape what Claude does next.

- **When you are at the session**, a 5-hour limit at its warning level makes Claude ask how to go on. Claude offers to split the work when it divides at the next step, to wait when the limit would run out before the reset, and always to push through, which draws on paid usage. When pushing through is the only option, Claude goes on without asking.
- **When you are away**, Claude splits the work at the warning level. At the critical level Claude saves its place and stops, leaving a prompt you can paste to resume after the reset.
- **The 7-day limit** never holds up the work at hand. At its warning level or higher, Claude puts off optional heavy work, such as a [`/gaia-fitness`](/maintenance/fitness/) run or a batch of [`/gaia-debt`](/workflow/debt/) fixes.

GAIA also checks the limits before each phase of a [`/gaia-plan`](/workflow/plan/) plan and each time it starts the [Code Audit Team](/workflow/code-audit-team/), not only the first time a limit reaches a level.

### Using your own statusline

If you already have a global statusline (`statusLine.command` in `~/.claude/settings.json`), [`/setup-gaia`](/getting-started/setup-gaia/#7-statusline) asks which one draws the left side: GAIA's bar or yours. The answer applies to this machine only. The right side shows GAIA's nudges either way.

## The right side

The right side names GAIA commands that have work to do, so you don't have to remember upkeep. Each one is a nudge: an emoji, the command, and a short reason. The nudge clears once the command has done its work. `/update-gaia`, `/update-deps`, `/gaia-wiki`, `/gaia-cleanse`, and `/gaia-debt` also start when you ask Claude in plain language. `/setup-gaia`, `/gaia-fitness`, `/gaia-codify`, and `/gaia-residue` start only when you type them.

### Nudges

Nudges always appear in this order, which is also their priority when space runs out:

| Nudge | Shows when |
| --- | --- |
| <code style={{ background: '#1a1b26' }}><S c="#f0abfc">⚙️ /setup-gaia (2 choices pending)</S></code> | A setup choice is waiting for this machine, usually after a GAIA update adds one. Once setup has confirmed you are a repo admin, it also counts team settings no one has applied yet, such as the required CI checks. Other machines do not show those, because only an admin can apply them. See [`/setup-gaia`](/getting-started/setup-gaia/). |
| <code style={{ background: '#1a1b26' }}><S c="#22d3ee">🚀 /update-gaia (2.1.0)</S></code> | A newer GAIA release is out. See [`/update-gaia`](/maintenance/update-gaia/). |
| <code style={{ background: '#1a1b26' }}><S c="#facc15">📦 /update-deps (4 outdated, 1 security)</S></code> | Packages are outdated or have open security advisories. See [`/update-deps`](/maintenance/update-deps/). |
| <code style={{ background: '#1a1b26' }}><S c="#4ade80">🔎 /gaia-cleanse (12 new memories)</S></code> | Claude's memory or startup files need a review. See [`/gaia-cleanse`](/maintenance/cleanse/). |
| <code style={{ background: '#1a1b26' }}><S c="#93c5fd">💪 /gaia-fitness (grade B+)</S></code> | Your Claude setup has something to improve, an update combined your edits with GAIA's in harness files, or your team has changed those files often since the last check. See [`/gaia-fitness`](/maintenance/fitness/#the-statusline-nudge). |
| <code style={{ background: '#1a1b26' }}><S c="#e879f9">🔨 /gaia-codify (2 recurring patterns)</S></code> | The audit keeps finding the same kind of problem. See [`/gaia-codify`](/maintenance/codify/). |
| <code style={{ background: '#1a1b26' }}><S c="#fca5a5">🐛 /gaia-debt (3 issues)</S></code> | Open `tech-debt` issues are waiting. See [`/gaia-debt`](/workflow/debt/). |
| <code style={{ background: '#1a1b26' }}><S>🧹 /gaia-residue (6 residuals)</S></code> | Trade-offs accepted at merge have piled up. See [`/gaia-residue`](/maintenance/residue/). |
| <code style={{ background: '#1a1b26' }}><S c="#67e8f9">🧠 /gaia-wiki (24 commits)</S></code> | The wiki has fallen behind the code. See [`/gaia-wiki`](/maintenance/wiki/). |

Each command's page explains what triggers its nudge and what the reason text means.

The `/update-gaia` nudge has three more forms:

- <code style={{ background: '#1a1b26' }}><S c="#22d3ee">🚀 /update-gaia (pull 2.1.0)</S></code>: a teammate already updated GAIA on `main`. Pull it instead of running a new update.
- <code style={{ background: '#1a1b26' }}><S c="#22d3ee">🚀 /update-gaia (resume 2.1.0)</S></code>: you have an unfinished update of your own. Running the command picks it up.
- <code style={{ background: '#1a1b26' }}><S c="#fde047">⌛️ GAIA 2.1.0 in progress (@teammate)</S></code>: a teammate is updating GAIA right now. There is nothing for you to run.

### Before setup is done

Until this machine has run its setup, the right side shows one nudge and nothing else:

<Row><S c="#f0abfc">⚙️ /setup-gaia (Required)</S></Row>

While [`/gaia-init`](/getting-started/gaia-init/) or [`/setup-gaia`](/getting-started/setup-gaia/) is running, the right side stays empty. If a session ends partway through setup, the nudge comes back within two hours.

### In a linked worktree

Maintenance commands run from the main checkout, so a linked worktree shows no nudges. The one exception is <code style={{ background: '#1a1b26' }}><S c="#f0abfc">⚙️ /setup-gaia (Required)</S></code>, which shows everywhere until setup is done.

### On a narrow terminal

When the nudges do not fit, they shrink one step at a time, starting with the lowest-priority one:

1. The full form: <code style={{ background: '#1a1b26' }}><S c="#facc15">📦 /update-deps (4 outdated, 1 security)</S></code>
2. A shorter reason, when the nudge has one: <code style={{ background: '#1a1b26' }}><S c="#facc15">📦 /update-deps (5)</S></code>
3. The command alone: <code style={{ background: '#1a1b26' }}><S c="#facc15">📦 /update-deps</S></code>
4. The emoji, with its count when there is one, in the default text color: `📦 5`
5. Hidden, and counted in a `+N` at the end of the row

A narrow row might look like this:

<Row>🚀 │ 📦 5 │ 🐛 3 +1</Row>

A teammate's GAIA update in progress never shrinks past <code style={{ background: '#1a1b26' }}><S c="#fde047">⌛️ GAIA 2.1.0 (@teammate)</S></code>, so you always see who is on it.

## When it updates

- **Every 15 seconds**, Claude Code redraws the statusline, so a resized terminal or a new context reading shows up within that time.
- **Every 6 hours at most**, the main checkout refreshes the nudges in the background.
- **When a command finishes**, it clears or refreshes its own nudge, so you are not told to run something you just ran.
- **The `/gaia-debt` count** also refreshes after Claude files, claims, or closes an issue, and at the start of each session.

The redraw is a local script that reads cached nudges: it uses no tokens, no network, and no `pnpm` command.

## Installing it

[`/gaia-init`](/getting-started/gaia-init/) adds the statusline to the project's `.claude/settings.json`. [`/setup-gaia`](/getting-started/setup-gaia/) sets it up on each machine and warns you when another statusline overrides it, such as a `statusLine` in `.claude/settings.local.json`.
