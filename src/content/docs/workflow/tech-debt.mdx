While Claude works on one change, it often notices a real problem somewhere else: in a caller of the function it edited, in a test next to the file, in a page of the wiki. Fixing it in the same pull request would mix unrelated work into the change. Ignoring it loses it. GAIA records it as a `tech-debt` issue on GitHub, so it gets fixed later, on its own branch, with its own review.

Two commands work through the debt:

- [`/gaia-debt`](/workflow/debt/) fixes `tech-debt` issues.
- [`/gaia-residue`](/maintenance/residue/) reviews findings that were recorded without being filed, and turns the ones that matter into issues.

## Where debt comes from

| Source | What it files |
| --- | --- |
| The [Code Audit Team](/workflow/code-audit-team/) | Problems a member finds outside the pull request's own change, in a file it opened while reviewing it |
| The audit loop | The findings left open when you choose **Stop and file the remainder** at a [branch checkpoint](/workflow/code-audit-team/#the-branch-checkpoint) |
| [`/gaia-cleanse`](/maintenance/cleanse/) | Problems outside what it may change, such as an instruction file that contradicts the wiki |
| [`/gaia-wiki`](/maintenance/wiki/) | Lint findings in files outside the wiki, which a wiki branch cannot change |
| [`/gaia-residue`](/maintenance/residue/) | A recorded residual you choose to **Promote** |
| You | Anything you ask for, such as "file this as tech-debt" |

The audit files problems only in files it opened to review the change, such as a caller, a test, or an importer. It never searches the rest of the codebase for debt.

## What gets recorded instead of filed

Two kinds of finding are recorded in the pull request's description instead of filed, so the backlog does not fill with problems the next change will find again:

- **Accepted residuals**, under `## Accepted residuals (recorded, not fixed)`: findings in the change's own scope accepted as a known trade-off, by the [audit loop's own stop](/workflow/code-audit-team/#the-branch-checkpoint) or by you.
- **Waived findings**, under `## Out-of-scope machinery findings (recorded, not filed)`: a non-security finding in GAIA's own audit files, or in a file the pull request already changes. A finding the change caused is never waived, and neither is one the change marks in a comment as handled elsewhere.

Both are **residue**. Nothing is lost: once a residual is 30 days old, [`/gaia-residue`](/maintenance/residue/) asks you to dismiss it, keep it, or promote it to a `tech-debt` issue. This keeps the backlog short enough that someone reads it.

## How an issue is filed

Every source files through the same `file-tech-debt` skill. Ask Claude to file something as tech debt to use it yourself. It:

- **Keeps your branch's own code out of the backlog.** A non-security finding on a line the branch wrote [is not filed](/reference/gates/#tech-debt-on-the-branchs-own-code): Claude fixes it or records it as an accepted residual.
- **Prevents duplicates.** A finding that already has an open issue, or one closed as not planned or labelled `wontfix`, is not filed again.
- **Labels the issue** with `tech-debt`, a severity, a footprint (how much code the fix touches), and a difficulty when the filer read the cited code. See [Labels](/reference/labels/#tech-debt).
- **Writes a self-contained body**: the file and line, what goes wrong under `## Problem`, and the suggested fix under `## Fix`.

When GitHub has a temporary problem, the finding is retried on the next audit round. With no issue tracker to file to (no GitHub repository, `gh` not signed in, Issues turned off, or no write access), nothing is filed and the run says so.

### Security findings

A security-sensitive finding (missing authentication, injection, an exposed secret, and the like) is filed **only when the repository is private**. Otherwise it goes to a local record under `.gaia/local/audit/security/`, with secrets removed, and you are told how many there were and where. A finding that might be security-sensitive is treated as one.

<Aside type="note">
An issue filed while the repository is private becomes public if you later make the repository public. Review your open `tech-debt` issues before you change its visibility.
</Aside>

## Investigate issues

When a finding's severity turns on a fact about the code nobody has checked yet, it is filed as `severity:investigate`, with the open question and what would settle it. At most three can be open at once; past that, Claude grades the new finding itself from the code. `/gaia-debt` never offers an `investigate` issue until it has a real severity. To re-grade one, see [`/gaia-debt`](/workflow/debt/#labels).

## Working through the debt

- When `tech-debt` issues are open, the statusline shows <Nudge cmd="gaia-debt" text="🐛 /gaia-debt (N issues)" />. Run [`/gaia-debt`](/workflow/debt/) to fix them, most severe and oldest first.
- When 5 or more residuals are 30 days old, the statusline shows <Nudge cmd="gaia-residue" text="🧹 /gaia-residue (N residuals)" />. Run [`/gaia-residue`](/maintenance/residue/) to decide each one.
- When the same kind of finding keeps coming back, [`/gaia-codify`](/maintenance/codify/) proposes a guard so it stops recurring.
