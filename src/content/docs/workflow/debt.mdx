`/gaia-debt` fixes the `tech-debt` backlog: the GitHub issues GAIA files for real problems found outside the change at hand ([how they are filed](/workflow/tech-debt/)). Each run fixes **one unit**: a single issue, a batch of related issues, or a batch of small unrelated ones. It works on its own branch, passes the same audit as any feature, and merges. The pull request carries one `Closes #N` per issue, so the merge closes them.

## When to use it

When open `tech-debt` issues exist, the statusline shows:

<Nudge cmd="gaia-debt" text="🐛 /gaia-debt (N issues)" block />

`N` leaves out issues already being worked on (`in-progress`) or parked for a SPEC (`debt:spec-pending`, `debt:spec-active`).

## How to invoke

```
/gaia-debt
```

Claude orders the backlog and offers the top of it as a menu. When the top issue belongs to a group of related issues (the same file, or the same directory and kind of finding), the group is offered too.

The menu can also offer a **batch of small issues**: unrelated issues graded `severity:minor` (or with no severity), none `difficulty:hard`, fixed together in one pull request. Claude fills it in backlog order up to the same size limit as a batch you name yourself, and offers it only when at least two issues or groups fit. It is never the recommended choice. Issues whose cited file is gone, issues that need a SPEC, and, on a repository not confirmed private, security-sensitive issues are left out.

```
/gaia-debt 142
```

One issue number fixes that issue. If it leads a group of related issues, Claude offers to fix the group with it.

```
/gaia-debt 142 157 161
```

Several numbers make your own batch, in one pull request. If it is over the size limit, Claude offers smaller subsets or lets you go ahead anyway.

Add `worktree` or `branch` at the end to choose where the fix happens, for example `/gaia-debt 142 branch`. Your team's [isolation policy](/workflow/work-lifecycle/#3-isolate) can still override it.

An issue number stops the run, with the reason, when it is not an open `tech-debt` issue in this repository, is already claimed, is parked for a SPEC, or is graded `severity:investigate`.

## How the backlog is ordered

A plain sort:

1. **Severity**, highest first: `severity:critical`, then `severity:major`, then `severity:minor`. No severity label sorts with minor.
2. **Age**, oldest first.

Issues that are `in-progress`, parked for a SPEC, or graded `severity:investigate` are never offered. When only `investigate` issues are left, Claude lists each one's open question.

An offer marks an issue whose cited file no longer exists as `[stale: path gone]`.

## What one run does

1. **Claims** every issue in the unit with the `in-progress` label as soon as you pick, so a teammate's session never starts the same issue. A claim left by a session that died is released by the next run.
2. **Re-checks each issue against your code.** Every `file:line` the issue cites must still say what the issue claims, and a newer comment that corrects the issue wins. If anything doesn't match, Claude releases the claim and stops, because only you can decide whether the issue or the code is wrong. In a batch, that issue is dropped and the rest continue.
3. **Sets aside security issues.** On a public or internal repository, a security-sensitive issue is never fixed in a public pull request. Its claim is released, and you are told only how many there were.
4. **Checks the size.** An issue big enough to need a design goes to [`/gaia-spec`](/workflow/spec/) instead: Claude prints what to run next and parks the issue under `debt:spec-pending`, then `debt:spec-active` once the SPEC is underway.
5. **Creates a branch**, `debt/<n>-<slug>`, or `debt/<a>-<b>-batch` for any batch, in a worktree by default.
6. **Fixes** every issue, runs the Quality Gate once over the whole change, commits, and opens a draft pull request. The commit type is the type of the change (`fix`, `refactor`, `test`), never `debt`. A batch of small issues gets one commit per issue or group; parts that touch the same file share a commit.
7. **Audits and merges** without asking you again, checks that the merge closed exactly the intended issues, and cleans up.

The claim stays while the work is unfinished: the audit stopped at its branch checkpoint, a merge is queued, or a check failed. Closing the pull request without merging releases it.

The run ends with a [cost line](/models-and-context/cost/).

Claim `tech-debt` issues only through `/gaia-debt`. A claim you set by hand looks abandoned, so the next run releases it.

## Labels

What each label means is in [Labels](/reference/labels/#tech-debt). The grades are guidance: Claude can change a footprint after reading the code.

To return a `severity:investigate` issue to the backlog, answer its question and have Claude re-grade it:

```text
Issue #<n> is graded severity:investigate. The answer to its question is: <answer>. Re-grade it to the right severity and put the answer in the issue body.
```
